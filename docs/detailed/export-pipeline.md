# LLMエクスポートパイプライン詳細 (Export Pipeline)

出力フォーマット仕様は [export-format.md](export-format.md) を参照。
本書は実装の処理フローと分割アルゴリズムを定義する。

## 1. 全体フロー

```
scanProjects → Glob / 拡張子 / 除外 → ソート
  → ファイルを逐次読み込み・断片をBlob化 → 仮梱包
  → 完成パートの実測検証・必要時再分割 → パート番号確定
  → index / CSV / report → ZIP
```

`export-common.js` がXML解析と分割helper、`export-consolidator.js` が本文生成、`export-format.js` が索引・CSV、`export-llm.js` が収集と統括を担当する。

スキャンはファイルサイズを取得し、本文生成時にも実ファイルサイズを検証する。読み取り失敗・単一ファイル上限超過を処理結果として返す。索引・対象CSV・集計は成功結果を使い、`export_report.csv` に除外・失敗も記録する。全件失敗・除外でも索引とレポートをZIP化する。

## 2. 分割と保持量

- 各ファイルを読み込み、UTF-8に変換してバイト・単語予算で断片化する。
- 断片の本文はBlobで保持し、全ファイル分の文字列を保持しない。
- 概算ヘッダー予備8KiB、本文単語ターゲット43万語で梱包する。
- 件数は断片数ではなく、異なる元ファイル数で数える。
- 末尾が小さい場合は、本文メタデータを使って直前と結合・再配分する。
- パート単位でBlobから本文を読み戻して完成テキストを作り、BOM3バイトを含む容量・推定50万語未満・件数上限を検証する。
- 超過パートはファイルブロック単位で再分割する。単一ブロックの場合は元本文をUnicodeコードポイント単位で分け、フェンス・見出しを作り直す。
- 分割ラベルを全パートにまたがって再採番する。総パート数変更後も最終検証を再実行する。
- ヘッダーが収まらない容量では明示的に失敗し、超過ファイルを成功扱いにしない。

文字列の保持は主に1ファイルと1パート分。元断片Blob・結果Blob・ZIPは保持するため、全体メモリは総容量に依存する。`assignParts` は概算ユーティリティとして残るが、本文の最終境界・パート数は実測検証後に確定する。

## 2b. RAG向けブロック構造

- フェンス保護: 本文にフェンス記号が含まれる場合は自動で長いフェンスに切り替える。
- パス付きフッター: 各ブロック末尾に `*End of file \`path\`*` を付け、チャンク切断面のどちら側でも帰属が復元できるようにする。

## 3. パートヘッダーの自己記述性

各パートは単体で意味が通じるよう、以下をヘッダーに含める。

- Frontmatter（パート番号/総数、件数、バイト数、entry points）
- 概要（ルート、モード、総件数/当パート件数、index参照）
- 当パートのファイル目次テーブル
- 当パートのディレクトリサブツリー（ASCII図、300行で打ち切り明示）
- 32パート以下の場合のみ全パートマップ（各パートの件数＋主要ディレクトリ）

## 4. indexのシャード分割

All Filesテーブル行単位でパート容量上限に収まるよう分割する。

- ルート `index.md` は `okf_version: "0.2"` と文書リンク付き目次のみ。
- 概要は `codebase.md`（概要＋ディレクトリ集計＋パートマップ＋先頭行群）。
- 複数時は先頭が `codebase.md`（概要＋集計＋先頭行群）、後続が `index_files_002_of_N.md` …（目次・概要へのリンク付きシャードヘッダー＋行群）。
- Summaryにシャード数を追記する。

## 5. 設定項目

| キー | 既定 | 意味 |
|---|---|---|
| `maxPartSizeMB` | 4 | 保存設定は0.01〜50MiB。プレビューの0＝一括 |
| `maxFilesPerPart` | 1000 | パート件数上限（0＝無制限） |
| `maxSingleFileSizeMB` | 1 | 単一ファイル上限（超過分は除外） |
| `sourceExtensions` | 既定セット | 対象拡張子（カンマ区切り） |
| `excludePatterns` | 既定セット（下記） | 除外Glob（スペース区切り、空文字＝無効） |

既定の除外パターン: `**/node_modules/** **/dist/** **/build/** **/out/** **/target/** **/__pycache__/** **/.venv/** **/*.min.js **/*.min.css **/*.bundle.js`

## 6. 文字コード変換

統合本文のデコードは UTF-16 BOM優先 → UTF-8（strict）→ Shift_JIS → EUC-JP → UTF-8（non-strict）の順で試行する。一覧表示用の4KBヒューリスティクス（`Detect`）とは別系統であり、結果が異なる場合がある。

## 7. OKF v0.2メタデータ

ルート目次以外のMarkdownには `type`、`title`、`description`、`generated`、`sources` を付ける。`generated.at` はエクスポート全体で共通、`generated.by` は `process:fileflow-export`。入力元はローカルスナップショットの範囲記述とし、入力ファイルの更新日時が取得できた場合のみ `last_modified` を付ける。独立検証を行っていないため `verified` は付けない。これらのメタデータを含む完成出力で分割上限を検証する。
