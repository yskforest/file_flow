# LLMエクスポートパイプライン詳細 (Export Pipeline)

出力フォーマット仕様は [export-format.md](export-format.md) を参照。
本書は実装の処理フローと分割アルゴリズムを定義する。

## 1. 全体フロー

```
scanProjects → フィルタ (Glob + 拡張子) → 割付 (assignParts)
  → パート単位ストリーミング生成 (consolidate)
  → index生成 (必要時シャード分割) → CSV生成 → ZIP化
```

1. **スキャン** (`scanProjects`): 全エントリを走査し、vcxproj系の検出・XML解析と並行して全ファイルのサイズを収集する。ファイルサイズはこの時点で確定するため、後段は再読み込みしない。
2. **フィルタ**: ツールバーのGlobフィルタと対象拡張子設定で範囲を絞る（プレビューに適用条件を表示）。
3. **割付** (`assignParts`): I/Oなしでパート境界を確定し、`totalParts` を先に fix する。
4. **生成** (`consolidate`): パート単位でファイルを読み→デコード→ブロック化し、完了パートから即Blob化する（同時保持は1パート分＋結果のみ）。
5. **索引・梱包**: index（必要時分割）、CSV2種、パート群をZIP化する。

## 2. 二重制限の割付アルゴリズム

ブロック概算バイト `≒ ファイルサイズ ＋ 512（メタデータ overhead）` を用い、以下いずれかに抵触したら改パートする（非空パートのみ）。

- パート累積がパート容量上限（`maxPartSizeBytes`、0＝無制限）を超える
- パート件数がパート件数上限（`maxFilesPerPart`、既定1000、0＝無制限）に達する

実測バイトは生成時に正確に計測する。概算誤差で上限をわずかに超える場合は許容し、再分割は行わない（`totalParts` の正確性を優先）。プレビューの推定パート数は `max(容量見積り, 件数見積り)` で算出し、律速要因を表示する。

## 3. パートヘッダーの自己記述性

各パートは単体で意味が通じるよう、以下をヘッダーに含める。

- Frontmatter（パート番号/総数、件数、バイト数、entry points）
- 概要（ルート、モード、総件数/当パート件数、index参照）
- 当パートのファイル目次テーブル
- 当パートのディレクトリサブツリー（ASCII図、300行で打ち切り明示）
- 32パート以下の場合のみ全パートマップ（各パートの件数＋主要ディレクトリ）

## 4. indexのシャード分割

All Filesテーブル行単位でパート容量上限に収まるよう分割する。

- 単一時は従来通り `index.md` のみ（概要＋ディレクトリ集計＋パートマップ＋全行）。
- 複数時は先頭が `index.md`（概要＋集計＋先頭行群）、後続が `index_files_002_of_N.md` …（`index.md` への参照付きシャードヘッダー＋行群）。
- Summaryにシャード数を追記する。

## 5. 設定項目

| キー | 既定 | 意味 |
|---|---|---|
| `maxPartSizeMB` | 4 | パート容量上限（MB、0＝一括） |
| `maxFilesPerPart` | 1000 | パート件数上限（0＝無制限） |
| `maxSingleFileSizeMB` | 1 | 単一ファイル上限（超過分は除外） |
| `sourceExtensions` | 既定セット | 対象拡張子（カンマ区切り） |

## 6. 文字コード変換

統合本文のデコードは UTF-8（strict）→ Shift_JIS → EUC-JP → UTF-16LE/BE → UTF-8（non-strict）の順で試行する。一覧表示用の4KBヒューリスティクス（`Detect`）とは別系統であり、結果が異なる場合がある。
