## メモリ測定（OKF v0.2対応前のBlob保持改善時）

```sh
docker run --rm --init --network none fileflow-test node --expose-gc test/memory.js
```

128ファイル × 512KiB（合計64MiB）の生成ソースを処理。パート上限4MiB、件数上限1000。変更前はコミット `122c4b0` の `js/export-llm.js` を同じコンテナ・同じベンチマークで読み込んで比較した。

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| 出力パート数 | 43 | 43 |
| サンプリングしたピークヒープ | 280.5MiB | 38.3MiB |
| サンプリングしたピークRSS | 550.4MiB | 296.4MiB |
| 所要時間（単回） | 1.408秒 | 1.751秒 |

本文断片のBlob保持と、単語カウント時の巨大配列生成の削減でヒープ使用量を減らした。値はNodeでの単回・10ms間隔と進捗コールバックによる測定であり、実際のピークを取り逃がす可能性がある。ブラウザやデータ分布で値は変わる。Blob・結果・ZIPは保持するため、総メモリが一定になる保証はない。

## 実装上の境界

- 本文と索引は最終サイズを検証する。CSVは推定50万語未満を検証し、パート容量設定は適用しない。
- ヘッダーや単一索引行を収められない容量はエラーにする。
- 文字コードの自動推定には曖昧さが残る。UTF-16はBOMを優先する。
- ブラウザ操作検証はChromiumで実施。Firefox/Safariの実操作検証は含まない。

## OKF v0.2追加検証

- Node統合試験と実ブラウザのダウンロードZIPをYAMLパーサーで解析。
- ルート `index.md` のfrontmatterが `okf_version: "0.2"` のみであることを確認。
- 概念文書の `type`、`generated.by/at`、`sources`、独立検証情報を捏造していないことを確認。
- 引用符・バックスラッシュを含む名前のシリアライズ、ルート目次のリンク先と実ファイルの一致、`.txt` 出力拒否を確認。
- 全件読み取り失敗時も `codebase.md` と処理レポートを保持。
- 語数はローカルの推定値であり、外部サービスへの取り込み可否・回答精度はこのテストの対象外。
